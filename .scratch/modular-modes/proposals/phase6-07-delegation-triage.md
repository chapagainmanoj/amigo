## Decision and evidence

Do not introduce nested Mode sub-agents, a `delegates` registry or a read-only Tool-marking system
without a demonstrated case the existing boundaries cannot express. Issue 07 explicitly permits
Do Not Build when shared Turn Context is enough. No concrete failed use case or delegation demand
is recorded in the issue. Its example is an owned question, “what is on today?”, rather than a need
for another independently reasoning agent.

The code already exposes declared asynchronous Turn Context providers. `todays_tasks` reads an
owned task block through the Store; providers are selected by a Mode contract. That establishes a
read mechanism, not permission to silently give Coach every Daily capability or transcript.
Use an explicitly approved minimal provider when the participant asks to consult their Tasks and
the Mode's data contract permits it. Otherwise use the participant-visible confirmed handoff to
Daily. Anything that writes continues through the destination Mode's Tools/Commands and explicit
handoff consent.

Nested model execution would add another prompt-injection surface, data-sharing decision, token
budget and failure path while producing plain text that still needs checking. It would not itself
solve ownership, read scope or consent. Calling something “read-only” without independently
removing write-capable implementations would create a weaker boundary than current declared
Toolsets.

## Acceptance of this triage outcome

Document which permitted provider or handoff covers a requested bounded question. Keep tests that
Coach cannot gain Task/Reminder write Tools and that a handoff alone cannot authorize undeclared
Tools or cross-account reads. Preserve Mode-scoped Session history.

Reopen only with a concrete reproducible participant job, the insufficient provider/handoff path,
its data-sharing approval, and evidence that bounded delegation solves it. Before implementation,
specify a depth-one hard limit, declared typed outputs, source/destination data allowlists, a
single Turn budget, timeout/cancellation behavior, no writes and per-Mode eval evidence. None of
those controls is presumed implemented by this record.
